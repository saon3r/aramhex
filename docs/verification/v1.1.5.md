# v1.1.5 acceptance record

Status: implementation in progress; no v1.1.5 release is claimed yet.

## Scope and exclusions

Selective intent-ports from upstream `9fe96f3`: calibration/duplicate-card guards,
transient OCR recovery, foreground-only game badges, sample-confidence wording and
well-supported spell combinations. Include issue #18's conservative cards-present
failure notice and refreshed bundled statistics.

Windows OCR, fixed1600px detection normalization, privacy/network restrictions and
the existing full-screen layer architecture remain intact. Renderer/DPI redesign,
RapidOCR-specific optimizations, cloud flags and expanded log collection are excluded.
The separate 4K performance question requires measured before/after evidence, not
assumptions from another user's upstream bug report.

## Proof, not just a successful game

- Baseline `1af0c2a`: **622 tests passed** before implementation.
- Required regression inputs: overlapping/invalid/hostile saved calibrations,
  duplicate augment identities, unchanged-pixel transient two-column OCR misses,
  actual disappearance and two-card full-scan recovery.
- New regressions must fail under pre-fix behavior and pass after the fix; preserve
  failing commands/output alongside each worker's report.
- Cards-present warning requires independent pixels, sustained failure and bounded
  once-per-game logging/notification. Tests must cover ordinary/empty/dark frames,
  brief transitions, partial recognition, missing OCR and notification re-arming.
- Band/global/PBE/incomplete-offer cases must preserve numeric recommendations while
  making confidence clearer.
- Refreshed bundle: all manifest hashes, cold-offline startup and frozen recognition.
- Fresh full suite, native Windows fixture/render and packaged18/18 acceptance.
- One live debug game is integration smoke only; it is not proof of intermittent
  recognition correctness. Any game/Alt-Tab checks will be agent-managed.
