# v1.1.6 acceptance record

Status: released and verified, 18 November 2026.

## Scope

From the review of upstream releases 1.1.3 to 1.1.9 (head `5b5d37d`; the full assessment
is in AGENTS.md):

1. **New augments on the English client.** This bug was found during the review; it is
   not an upstream port. The English OCR matcher read names only from the bundled
   `i18n.json`, so augments added after a build could not be matched until a release.
   The matcher now falls back to CommunityDragon `name_en` (an existing allowed host).
   The store fetches names as soon as new stats bring an unnamed ID, retrying at most
   hourly. Six 16.22 names were added to the bundle, and retired names are kept.
2. **Overlay focus.** This ports the intent of upstream 1.1.9: WS_EX_NOACTIVATE on the
   icon and details windows, activatable only while typing in the champion search.
   Upstream's cloud switch is not ported.

There are no new hosts, no telemetry and no change to the recognition pipeline. The
committed bundle stays at 16.21. The release workflow refreshed it at build time, so the
published build ships 16.22 (57,823,093 games, snapshot 17 November).

## Results

- **Tests.** Full suite: **745 passed**, and `git diff --check` is clean. Each new
  regression failed before its fix: the English matcher fallback, prompt and hourly name
  fetching, and the no-activate and typing state transitions.
- **Data feed.** An isolated `--refresh` against the live feed downloaded patch 16.22
  (57,823,093 games), and the fixture scan gave advice.
- **Native style check.** Both overlay windows carry WS_EX_NOACTIVATE, and showing or
  expanding the panel left the foreground unchanged.
- **Independent review.** No significant findings. There were two low-severity notes.
  If no game or client window exists while typing, the panel can auto-collapse. An
  augment that has no English name anywhere costs one dictionary fetch per hour.
- **Local portable build.** `AramHex-Portable-1.1.6.zip` passed **18/18** in
  `accept_packaged.py` on two consecutive runs.
  - One earlier run scored 17/18 on "warmed start opens no TCP connections". Its log
    shows only the existing new-stats offer check (`_look_for_offer` reads the manifest
    even with updates off). Newer 16.22 stats now exist, so that read happens and can
    still be open when the check samples. No augment-name fetch was logged in that run.
  - Another run used an empty, non-warm home by mistake and is not counted.
- **Live game (packaged EXE, portable userdata, `--debug`).** On first start the app
  downloaded the 16.22 stats. The game then covered champion select and 15 evaluated
  offers, with **zero warnings or errors**.
  - **One Hit Wonder**, a 16.22 augment that was unmatchable before this fix, was
    recognised. Its badge rendered correctly (`-2.7 · 47.8% win rate`, `Gold win-rate
    #34/57`).
  - The owner clicked the in-game icon to expand and collapse it, and recognition
    continued without interruption.
  - Debug captures stayed in the throwaway portable folder and are not committed
    (they contain other players' names).

## Release

- **First release run failed** (`44285578516`, tag on `4136eea`). The release
  workflow refreshes bundled stats before running the tests, and
  `test_parse_augments_selects_by_active_id_not_aram_or_kiwi_heuristic` hard-coded
  Cherry card 2091, which 16.22 no longer contains. Normal CI had passed on the same
  commit.
  - PR #34 made the test use the Cherry cards still present in the bundle. The suite
    passed **745** against both the committed 16.21 bundle and a refreshed 16.22
    bundle.
  - No release had been published, so the tag was moved to merge `024d584`.
  - Upstream's own `v1.1.6` to `v1.1.9` tags had been fetched locally and blocked the
    first tag attempt. They were deleted locally (never pushed), and the upstream remote
    now fetches no tags.
- **Release run `44286687291` succeeded.** It published `AramHex-Portable-1.1.6.zip`,
  `AramHex-Setup-1.1.6.exe` and `SHA256SUMS.txt`.
- **Downloaded assets.** Both checksums match. The portable note is English and keeps
  `userdata` during upgrades. The bundled manifest is 16.22 / 57,823,093 games.
- **Downloaded portable EXE in `accept_packaged.py`.** It scored **18/18** in seven of
  eight runs.
  - The single miss was again "warmed start opens no TCP connections", and that run's log
    shows no augment-name fetch.
  - With updates off, the app still reads the stats manifest so it can offer newer data
    (`PublicStore._look_for_offer`; behaviour that predates this release). This
    intermittent check catches that read when the connection is still open at the
    18-second sample.
  - Tightening either the check or that behaviour is a separate decision; it was not
    changed here.
- The installer was not executed.
