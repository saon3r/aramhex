# Development and releases

This describes **this fork**. Upstream's version of this file documented a self-updater, an
incremental-patching branch, Tencent data sources and a PBE overlay pipeline — all of which
were removed here. If you are reading upstream's history, do not follow it.

## Layout

```
lolhex/
  __main__.py           entry point (python -m lolhex)
  engine.py             coordinator: window state, champion-select recognition, card
                        recognition, recommendations
  config.py             settings file and directories (installed: %APPDATA%\AramHex;
                        portable: <program dir>\userdata)
  recommend.py          scoring for the three offered cards
  panel.py              single-champion panel (win rate, build, skill order, augment table)
  messages.py           translation helper: tr(key, **values)
  i18n.py               game-language name tables (data/i18n.json), used by recognition
  data/
    store.py            offline static seed, per-family refresh, atomic static.json cache
    metadata.py         Data Dragon / CommunityDragon parsers and English display helpers
    public.py           statistics: bundled + downloaded from the data repository, checked
                        file by file with SHA-256
    http.py             the only place outbound HTTP may originate
    bundled/            bundled statistics (generated by scripts/update_data.py — do not edit)
    messages.json       the UI message catalogue
  vision/               screen capture, champion-select recognition, card recognition, OCR
  ui/                   main window, tray, in-game overlay
scripts/update_data.py          refresh lolhex/data/bundled/ from the data repository
scripts/update_i18n.py          regenerate the game-language name tables
scripts/update_client_icons.py  regenerate client champion portraits
scripts/update_hero_icons.py    regenerate the bundled champion icon index
scripts/accept_packaged.py      acceptance suite for the built, frozen application
scripts/bench_ocr.py            OCR timing benchmark
packaging/                      PyInstaller spec, Inno Setup script, build script
```

## Principles

- **It reads the screen and nothing else.** No connection to the game client (not the LCU,
  not the in-game 2999 API), no memory reads, no injection, no synthetic input.
  - After a click on the overlay, focus is handed back to the game with
    `SetForegroundWindow` only; no input is sent.
- **Statistics use the public data format** described at the top of `lolhex/data/public.py`.
  Changing that format requires bumping `schema_version` in both repositories.
- **A network failure must not break the app.** Metadata falls back to the last cache, then
  to bundled data; statistics fall back to the bundled copy.

## Tests

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
.venv\Scripts\python.exe -m pytest
```

Tests do not touch the network: `conftest.py` installs a `no_network` guard. Tests that need
HTTP start a temporary local server instead.

## Packaging

Requires Inno Setup 6 (`winget install --id JRSoftware.InnoSetup -e`).

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements-build.txt
.venv\Scripts\python scripts\update_data.py     # refresh the bundled statistics
pwsh -NoProfile -File packaging\build.ps1
```

Output lands in `build/release/`:

- `AramHex-Setup-<version>.exe` — per-user installer, no administrator rights required
- `AramHex-Portable-<version>.zip`
- `SHA256SUMS.txt`

The build validates the bundled data first, then runs Qt's self-test through a real Windows
window plugin. If the self-test fails, no installer is produced.

## Releases

1. Refresh the bundled data: `python scripts/update_data.py`, then commit it.
2. Bump `__version__` in `lolhex/__init__.py` and write the entry in `CHANGELOG.md`.
   - Write it **for players**: one or two plain sentences about what changed or what was
     fixed. No file names, no internal numbers. It is shown on the release page and in the
     app's "new version" notice.
3. Commit, tag, push: `git tag v1.2.3 && git push origin v1.2.3`.
4. `.github/workflows/release.yml` then runs the tests, checks that the tag matches
   `__version__`, builds both artifacts, and creates the release with the `CHANGELOG.md`
   entry as its notes.
5. **There is no in-app updater in this fork.** Users take a new version from the Releases
   page. That is deliberate: the updater was removed along with the rest of upstream's
   remote-control machinery.

Refreshing the statistics does not require a release at all — the app downloads them on its
own schedule. Releasing only ensures that a fresh download starts with reasonably current
bundled data.
